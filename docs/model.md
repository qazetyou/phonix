# Model, sampling and error definitions

## Fixed reference and hearing approximation

The unmodified B&K 5128 diffuse-field curve is the calibration reference. A user-selected bass shelf is an independent preference applied after calibration. Data is bundled from [AutoEq's 5128 DF file](https://github.com/jaakkopasanen/AutoEq/blob/7ae0f56d53074872b028649617a22bbb4232feb7/targets/Diffuse%20field%205128.csv), with its MIT license and checksum.

The hearing baseline is the normalized magnitude response of the `ed_32000` middle-ear FIR from [LoudnessModel](https://github.com/MalcolmSlaney/LoudnessModel/blob/8370c866f66157b91a74e49d19441759556c7f77/transfer_functions.py). This response is defined for signals at the eardrum. An eardrum-domain baseline avoids applying an external-ear free-field response on top of a DF curve that already contains fixture anatomy. The source's BSD license is retained.

This program uses that response as a **linear sensitivity proxy**, not the complete Moore/Glasberg loudness model, an ISO 532 implementation or an individual hearing assessment. It does not model auditory-filter bandwidth, compression, hearing thresholds, absolute sound pressure, temporal integration or individual hearing sensitivity. Source values above 12.5 kHz are unvalidated extrapolation. New profiles default to 60–15000 Hz, with custom limits supported from 20–16000 Hz; low-frequency and upper-treble estimates remain experimental. Adding those regions does not make the population hearing baseline more accurate. [Moore's review](https://journals.sagepub.com/doi/10.1177/2331216514550620) describes the threshold and level dependence absent here.

The approximation favors a stable interpretation across profiles with NumPy as the only Python dependency. It does not establish personal acoustic diffuse-field neutrality. Headphone response, ear coupling and listener sensitivity remain inseparable from listening-only probes.

Files are SHA-256 checked at runtime. Source commits, derivation and licenses are recorded in `phonix/data/provenance.json`. The middle-ear table evaluates the 4097-tap FIR at 400 logarithmically spaced frequencies between 20 and 15000 Hz, plus 1000 and 12500 Hz, at the source sample rate of 32000 Hz. Gains are normalized at 1000 Hz. No upstream Python code executes at runtime.

The supported domain now reaches 16000 Hz. Between 15000 and 16000 Hz, sensitivity explicitly holds the bundled 15 kHz endpoint constant; this policy is recorded in provenance and flagged by `hearing_proxy_endpoint_held` in exports. The source table and checksum are unchanged, so all v1 values through 15 kHz retain their original interpretation. The DF target uses its existing data through 16 kHz. This extension supplies no additional validated hearing response and avoids treating the FIR's 32 kHz Nyquist endpoint as a new sensitivity measurement.

## Converting judgments into corrections

For a local, level-independent approximation in dB:

- `h(f)` is unknown effective headphone acoustic response at the listener's ear.
- `s(f)` is the assumed middle-ear sensitivity proxy.
- `m(f)` is the digital tone level needed to match a common perceived loudness.
- `t(f)` is the 5128 DF reference.

Assume `m(f) = -h(f) - s(f) + constant`. A pair measures `m(b) - m(a)` by holding tone A's digital level fixed and adjusting tone B. This transitivity is approximate: actual equal-loudness relationships depend on level, and a fixed digital reference does not guarantee equal reference loudness across frequencies or devices.

The estimated correction is:

```text
correction(f) = t(f) + s(f) + m(f) - overall_gain
```

Overall gain is removed with uniform weighting in log frequency over the selected range. Input attenuation for headroom is separate. Equal loudness is the probing technique, not the final sound profile.

The export target is `t(f) + bass_shelf(f)`. Its correction is the neutral estimate plus the same shelf; changing bass preference never changes the probing schedule, likelihoods, observations, inferred neutral curve or population baseline. A shared preference can therefore be used across device profiles without measuring them again. Any unmeasured bass region remains unmeasured.

For an identical listener sensitivity on two devices, this shared baseline yields matching corrected perceptual profiles in the simplified model, apart from gain. Both may retain the same systematic tonal error if the baseline is wrong. A synthetic regression test covers this cancellation; it is not real-listener validation.

## Adaptive comparisons and cross-checks

The shared-fit scheduler below describes `global-v1`, retained for legacy sessions. New CLI/UI profiles use the frozen regional method described next. The population hearing baseline and DF data remain identical.

### Frozen regional method (`regional-v2`)

Regions follow the same 250 Hz and 2 kHz boundaries and singleton rule. Within-region evidence is fitted independently, with overall gain removed inside each region. Passes run midrange, bass and treble order, omitting absent regions. A pass freezes only when its measured graph is connected with degree ≥2 at every node, at least two independent cycles, shape95 ≤ chosen shape tolerance / √2, and cross-check RMS ≤ the chosen disagreement tolerance. The √2 allocation is a conservative working rule, not validated acoustic accuracy. Potential local geometry is prepared atomically in the whole grid and each region before freezing; later geometry changes are prohibited while any frozen shapes exist.

Version-2 workflow metadata records stage, stage-start judgment index, per-region freeze judgment indices, and balance/verification checkpoints. A frozen shape is recomputed from its retained within-region evidence prefix, making its value and covariance stable and auditable. Post-freeze checks can detect disagreements but never update that shape silently. No curve snapshots from an unmeasured prior qualify as connected calibration.

Scheduling groups every check by category instead of rotating categories according to recent answer count. Local closing checks run midrange, bass, treble order, then boundary checks in low-to-high boundary order, omitting absent/skipped local regions. Complete the required distinct links and playback orders inside one category before selecting the next. Extra refinement stores `refinement_range` and `refinement_at`, finishing up to two distinct links in both orders inside the active category before selecting the next informative category. Global readiness can finish calibration early; its gates are unchanged. `comparison_range` identifies the active UI range/boundary. Metadata is saved only on accepted answers/skips or completion; cancellation cannot commit planning changes. Older checkpoints lacking these fields remain valid.

After freezing, let `u` concatenate region shapes, `C` their block covariance, `J` associate nodes with gain variables (midrange fixed to zero when present), and `D` contain cross-region difference rows. Each boundary comparison has posterior mean `y` and variance `V`. Fit only gains `g` in `y = D*u + D*J*g`. The effective boundary covariance is `diag(V) + D*C*Dᵀ`, preserving correlations caused by shared uncertain shapes. Six bounded robust reweighting passes solve generalized least squares. If `G` maps boundary residual observations to fitted gains, the combined matching curve is `u + J*G*(y-D*u)` and its covariance is `(I-J*G*D)*C*(I-J*G*D)ᵀ + J*G*diag(V)*Gᵀ*Jᵀ`. Global log-frequency gain is removed afterward. Every within-region difference, and its uncertainty, remains unchanged by gain fitting.

Balance requires two distinct usable links at each adjacent region boundary, each in both playback orders, followed by adaptive boundary-only refinement if needed. Verification takes a fresh local link per region and a boundary link per boundary in both orders. The global shape uncertainty, connectivity, degrees, cycles and disagreement gates still apply. Disagreement is the maximum of pooled RMS, within-region RMS and boundary RMS, preventing many good local edges from hiding a bad boundary. Strong repeated residuals exceeding disagreement tolerance plus a 95% shape/probe uncertainty allowance flag the involved regions for review. A tightened tolerance flags frozen shapes that no longer meet local checks.

Reopening a region retains all answers and other freeze checkpoints. Two fresh local links in both orders are required before freezing again. A new balance checkpoint then excludes earlier boundary evidence from current pair posteriors and gain estimation while retaining it on disk. Cancelled prompts use a deep copy of workflow state so advancing a pending freeze cannot modify a saved checkpoint. Reset clears observations and checkpoints while keeping configuration. Extending a range after freezing requires a new profile.

The frozen sampled curve is interpolated between region endpoints in log frequency by the existing PEQ fitter. There are no imposed rectangular region-gain steps in the rendered filter response. PEQ approximation may change sampled shape within numerical fit error. Shape locking does not solve individual-hearing or level-dependence limitations, and regional offsets remain relative matching levels, not measured acoustic gain errors.

### Explicit skipped local shapes

The UI can skip all local passes before a channel starts, or skip its active local pass with `k` and confirmation. Version-2 state stores `skipped` as a subset of `frozen` with identical judgment checkpoints. These checkpoints settle scheduling only; they do not assert a measured or verified shape. All original observations remain on disk, but local evidence in skipped regions is excluded from the current fitting graph. Reopening removes that region's skip checkpoint and requires fresh local checks and a new boundary epoch.

For a skipped region, set the matching shape to the centered `-(DF + sensitivity)` baseline solely as an explicit **no local correction** constraint. In `correction = DF + matches + sensitivity`, the frequency-dependent terms cancel, leaving only the regional constant determined by measured boundary links. No prior-only headphone response or fine-frequency correction is exported. Non-skipped regions still require connected measured local fits. Skipped regions must have measured regional connections, including the normal redundant boundary and fresh verification checks; a single-region range cannot use balance-only calibration.

The gain fit is conditional on that no-local-correction constraint. Its uncertainty uses measured probe variance and measured local-shape covariance; it excludes unknown deviations of skipped shapes from the assumed reference. Separately, the full shape covariance retains broad unknown uncertainty for skipped shapes. Their diagnostic shape intervals are unavailable, full-frequency connectivity remains false, and conditional balance uncertainty is reported separately. Completion gates for profiles with skips use settled measured shapes, connected regional gain evidence, conditional uncertainty and disagreement; they do not claim a complete measured local graph. Verification omits local checks only in explicitly skipped regions. Repeated contradictory boundaries still request regional review.

Export/preview explicitly distinguish this reduced correction scope and list all uncalibrated regions. Requested correction is flat within skipped regions before separate bass/voicing preferences; the existing continuous PEQ approximation can depart from that constraint within reported fit error. The `complete (shape skipped)` status means the selected reduced workflow passed its checks, not that all local shapes reached DF neutrality.

### Optional sound voicing

After calibration and verification, the user chooses Neutral/reference (no voicing), V-shaped (+3 dB low shelf at 180 Hz, +3 dB high shelf at 4 kHz), Warm tilt (+2 dB low shelf at 250 Hz, −2 dB high shelf at 2.5 kHz), or Bright (+2 dB high shelf at 3 kHz). These are preference presets with Q=1/√2, applied independently of the target and hearing model. The separate bass preference remains additive; Neutral/reference with nonzero extra bass is not the unmodified DF reference.

The total filter count reserves preference slots, fits only the neutral correction with the remaining slots, then appends exact preference filters. Preview/export and headroom use the whole cascade; correction-fit metrics continue to concern the neutral fit. Reports separate the neutral curve, bass preference, voicing curve and their sum, label preference-only behavior outside measured frequencies, and retain regional fit diagnostics. Selection or cancellation cannot alter calibration evidence. Legacy missing `sound_profile` fields default to Neutral/reference.

### Legacy shared-fit method (`global-v1`)

Begin with a log-spaced grid: 17 points for full-range sessions, 11 for bass, 9 for midrange and 7 for treble by default. Where the limits include 1 kHz, an interior point is replaced with that anchor (or the endpoint already supplies it). Above 12.5 kHz, another interior point supplies a 12.5 kHz anchor to bridge upper-treble comparisons within the level limits. Existing anchors and endpoints are preserved. Counts and limits are user-configurable. Bass sessions extend to 1 kHz to observe bass level relative to mids; full-range sessions link bass, mids and treble in one graph. Separate range profiles each lose their overall gain and cannot determine relative gains between regions without connecting comparisons.

Guided comparisons keep a discrete probability distribution for each pair's equality offset. The ternary logistic response model assumes a 1.5 dB noise scale, a ±0.75 dB equality region and a 4% lapse term. These are working defaults, not measurements of the individual listener. The next guided level minimizes expected posterior entropy among candidate posterior quantiles.

Manual matches use a 1.5 dB observation standard deviation. Repeated disagreement inflates variance. Pair estimates enter one weighted graph fit: frequencies are nodes, and measured differences are edges. Robust reweighting reduces contradictory edges' influence; the unidentifiable overall gain is removed.

Pair selection restricts every new pair to at most one octave (`higher/lower <= 2`, with a small floating-point allowance at the boundary). Within this local set, it scores approximate expected reduction in global shape variance per judgment, connects uncovered frequencies, adds alternative links and revisits discrepancies. Dividing the score by `1 + 0.25 * log2(higher/lower)` modestly favors shorter gaps among informative candidates; the hard distance limit provides the main bound on comparison difficulty. Cross-checks may span multiple grid intervals but never exceed one octave. There is no fallback to distant comparisons. The full curve is linked by overlapping local observations. This adapts [information-based active pair sampling](https://arxiv.org/abs/1711.05957) and [adaptive equal-loudness probing](https://pmc.ncbi.nlm.nih.gov/articles/PMC6200554/); it does not claim proven optimality for headphone calibration.

The listening scheduler groups frequencies below 250 Hz as bass, 250–2000 Hz as midrange, and 2000 Hz upwards as treble. A singleton endpoint joins the nearest populated region. It takes one early judgment on each of two available local links at each region boundary, then builds preliminary within-region coverage in midrange, bass and treble order. Within-region passes prioritize unmeasured links until measured components match the available local graph, each node has two local links where available, and at least one local cycle exists where possible. Historical uncensored local observations can supply this coverage. This is a coverage criterion, not independent convergence or a claim of precision within each region. Skips can reduce available local coverage; the unchanged global stopping criteria still require measured connectivity, two links per node, two cycles, shape uncertainty and disagreement tolerances.

Preliminary within-region coverage applies the same predicted-level guard as pair selection: unmeasured nonadjacent links above 95% of the offset allowance do not become required local checks. Existing uncensored links remain eligible for further probing. A region can advance to combined refinement when its currently playable coverage is complete; global connectivity, redundancy, uncertainty and disagreement requirements are still enforced.

Closing regional balance checks take fresh judgments on two distinct usable boundary links where possible, in both playback orders. Grouped verification then checks one usable local pair per region and one boundary pair per boundary in both orders before grouped adaptive refinement continues. Each category finishes its checks before the next category begins. Boundary checks favor short gaps and use other eligible local links if the predicted-level guard rejects a preferred new link. Both closing passes use the same individual tones and offset posterior as other comparisons. They do not equalize broadband regional loudness or change the target. Regions share the original fit and its single overall gain constraint; there are no independently normalized regional curves.

Per-channel workflow metadata records a version, stage and judgment index at stage entry. New judgments also record playback order; direction remains canonical for fitting. Fresh closing checks are counted only after the current stage checkpoint, excluding skipped and censored pairs. Cancellation, unsure answers and replays cannot supply a check or advance saved progress. All stages consume the existing judgment cap, and completeness/export guards require both global consistency and closing verification. Completed legacy profiles without workflow metadata retain their original interpretation; incomplete sessions adopt the scheduler on their next accepted comparison or skip without rewriting old observations. Export reports separate `consistency_thresholds_met`, `regional_checks_complete` and `calibration_complete` so a successful fit cannot hide unfinished verification.

Before selecting the first pair, and on later refinement calls, local-grid preparation examines possible one-octave links excluding skipped pairs and censored comparisons. It inserts geometric midpoints to bridge disconnected components, then to provide at least two possible partners per frequency, a common third local partner for each possible link, and two independent graph cycles. The third partner allows a short triangular cross-check instead of leaving a long interior chain with loops only at its endpoints. Preparation operates on a copy and commits only a complete plan within `max_points`; insufficient capacity raises a readable error without partially changing the grid. Added points have no observations and do not establish measured coverage. Existing frequencies, observations and skipped pairs are retained, including historical comparisons outside the new limit. All previously saved observations still participate in the fit under the existing censoring rules.

All observations are retained. Randomized playback order (or paired opposite orders during closing checks) is translated into a consistent stored direction. Replay, mode changes and unsure replies do not count as measurements. Pairs whose posterior presses against the offset boundary after at least six judgments are censored: their history is saved, but they are excluded from equality fitting and replaced by other links. They cannot establish otherwise unmeasured coverage. The predicted-offset guard skips new nonadjacent links likely to exceed playback limits; existing local links remain eligible for further checking until censoring is justified, so a few preliminary judgments cannot remain permanently unverified in the fit.

After local-grid preparation, once observed coverage is connected with redundant comparisons, a midpoint can be added where the reference contour or estimated correction suggests interpolation error. If a node has fewer than two observed links and fewer than two potentially reachable partners within one octave and 90% of the offset limit, this stage first adds a nearby midpoint to support a cross-check. This is useful at low bass where the estimated matching curve can be steep; playback limits stay fixed. This level/contour refinement still requires connected, sufficiently certain observed coverage, so geometric grid preparation does not rescue every inaudible or unreachable bass comparison. The default maximum is 32 points for full range, 21 for bass/midrange and 17 for treble. A sparse grid can miss narrow peaks between probes; reported uncertainty does not bound every unsampled feature.

Pair duration is `max(0.45 seconds, 15 / lower_frequency)`: at 20 Hz both tones last 0.75 seconds, preserving equal duration within the comparison. Ramps remain 20 ms and the inter-tone gap 0.25 seconds. Duration differences between pairs and real temporal integration remain outside the sensitivity model.

### Frequency-dependent probe levels

New CLI/UI profiles save `tone_leveling=adaptive-v1`; a missing field and low-level `Settings()` retain legacy `fixed` playback. Existing profiles are not migrated, and reset retains the saved configuration. No hearing-baseline or DF data changes are involved.

For each prompt, fit the current matching curve `m`, then freeze it until an answer is accepted. If 1 kHz lies in the grid's range, interpolate `m0 = m(1000)` in log frequency. Otherwise, evaluate the fixed prior on the grid plus 1 kHz and align its 1 kHz value to `m` using the log-frequency-weighted mean grid residual; this is a baseline anchor, not inferred device response outside the measured range. The desired canonical A level is `reference_level + m(a) - m0`. Before observations this uses the fixed hearing/DF proxy; usable observations gradually supply the fitted shape. The desired B level is A plus the existing adaptive or manual offset `d`. It approaches `reference_level + m(b) - m0` when `d` approaches the fitted equality difference.

For floor `L=-78` and saved ceiling `U`, choose actual A by clamping its desired level to `[max(L, L-d), min(U, U-d)]`; actual B is `A+d`. This common pair shift preserves the requested difference without waveform clipping or exceeding the existing offset allowance. When a manual adjustment reaches a bound, A can move as well as B; the UI explains this. The fitted prediction stays fixed within the prompt, and replay/help/unsure responses cannot change it. Bounds may prevent the estimated common perceived level from being achieved.

Accepted real comparisons record canonical `playback` metadata with method and `a_dbfs`/`b_dbfs` peaks, independent of playback order. Storage validates finite bounded peaks and agreement between their difference and the saved `offset`; old observations without metadata remain valid and unchanged. Pair likelihoods, graph inference and EQ conversion continue to use the actual B-minus-A offset. The starting gains are not an additional EQ correction. They introduce no new evidence for disconnected frequencies and do not change export guards.

This is a stimulus-presentation approximation, not a full level-dependent loudness model. It does not identify the listener's absolute SPL, individual sensitivity or the ear's compression. The population baseline, prior strength, fitting assumptions and stopping tolerances stay fixed. Common pair shifts and changing fitted predictions can still change perceived operating levels, especially at playback bounds.

## Music-volume preparation and reference-tone check

Music playback supports immediate Enter, Escape or `s` cancellation in curses and in an interactive terminal. The player drains PipeWire stderr while checking stop keys at 50 ms intervals; cancellation terminates/reaps the subprocess before deleting its temporary WAV, with kill fallback if termination stalls. The terminal returns to the volume setup screen, allowing replay from the beginning or explicit continuation. Ctrl-C retains its session-interruption behavior. Canceling music does not record an observation, adjust volume, consume the answer budget, or modify settings. Redirected stdin retains the original blocking playback behavior.

Before tone comparisons, every run offers a built-in 25-second music excerpt through the profile's selected output. The listener can adjust hardware/system volume and replay the same excerpt from its beginning, then explicitly continue. A resumed session asks the listener to restore the volume of earlier judgments. In particular, sessions begun with the previous pink-noise preview should retain their earlier hardware volume instead of establishing a new volume from the music. The preview contributes no observations, uncertainty estimates or budget usage.

The excerpt is **Vibe Ace by Kevin MacLeod**, source seconds 30–55, licensed under [Creative Commons Attribution 3.0](https://creativecommons.org/licenses/by/3.0/) with the recording's [accompanying attribution](https://github.com/librosa/data/blob/main/audio/Kevin_MacLeod_-_Vibe_Ace.txt). It is bundled as 48 kHz stereo PCM16 with short fades and measures -14.1 LUFS / -1.0 dBTP after offline normalization with true-peak limiting. This is a fixed typical normalized-music reference at 100% player volume, not an average measured from the user's music. Runtime playback uses the prepared file unchanged, independently of tone sample rate and reference-noise settings; PipeWire handles output resampling. The package includes attribution, modification details and checksums in `data/LICENSE-Music.txt` and `data/music_preview.json`. FFmpeg is needed only for optional offline preparation and measurement, not playback.

After accepting the music preview, every session plays a short 1 kHz tone in both channels, with the usual 500 ms startup silence. The listener keeps hardware/system volume fixed and confirms with Enter/c only when the tone is clearly audible and comfortable. This checks usability for comparisons, not the listener's hearing threshold. There is no mandatory narrow-band noise match or three-equal-judgment verification.

New CLI/UI profiles use a reference derived offline from the bundled music's 935–1065 Hz band. An FFT of each final PCM16 channel retains only that band at unit gain. Parseval's relation yields the full-excerpt mean-square energy, including fades and quiet intervals without gating; the two channel powers are averaged rather than downmixing the waveforms, avoiding phase cancellation. This band measures -41.48575 dBFS RMS. For a steady sine, `peak_dbfs = band_rms_dbfs + 10*log10(2)`, giving -38.47545 dBFS peak, rounded to -38.5 dBFS for setup. Its default ceiling is 18 dB higher (-20.5 dBFS). Short-tone ramps reduce its time-mean energy slightly. The band boundaries, averaging method and unrounded levels are saved with the asset checksum in `music_preview.json`; startup reads metadata rather than analyzing PCM. This energy approximation does not establish perceived loudness equivalence, acoustic SPL or representative levels for every music recording.

The new defaults apply only to newly created CLI/UI profiles and an explicit Default tone levels selection before any judgments. Existing saved references remain unchanged, including sessions with no judgments. Legacy missing fields and low-level `Settings()` retain -42/-24 dBFS; reset retains the profile's existing configuration. Explicit creation flags override derived defaults. A custom starting reference without an explicit ceiling retains 18 dB of headroom where the -3 dBFS cap permits.

Before any judgments, explicit `+`/`-` or `++`/`--` commands change the reference by 1 or 3 dB and replay it. Replay and help never alter gain. For initial comparison allowance `a`, adjustments span `max(-60, -78+a)` to -9 dBFS peak, with ceiling `min(-3, reference+a)`. The usable allowance shrinks at high references but never below 6 dB. Bounds cause feedback without an extra gain change or clipping. No automatic gain adjustment is made in response to audibility.

Reference and ceiling changes remain drafts until explicit confirmation; cancellation, playback failure or interruption discards those drafts. Accepted levels are saved before frequency comparisons begin, including when the listener exits before recording any judgment. Subsequent runs reuse those levels. Once either channel has judgments, the reference, ceiling and sample rate are locked: the check offers replay, help, confirmation or return. An unusable saved level requires a new profile rather than changes to a session containing earlier judgments. Preparation records no calibration observations and uses no judgment budget.

This replaces the old reference-noise match to reduce setup effort. It does not establish equal acoustic reference loudness across devices or demonstrate more accurate correction. The fixed sensitivity proxy assumes level independence even though actual hearing is level dependent; choosing substantially different operating levels may reduce comparability. A consistent starting level, adjustments only when needed, and saved-level locking support repeatability without validating that assumption. Neither preparation step changes the hearing baseline, target or interpretation of frequency comparisons.

Legacy `noise_level` and `noise_ceiling` fields and command arguments are retained and validated for saved-profile/script compatibility, but have no effect on current calibration preparation. Noise settings are hidden from the UI. Existing sessions preserve their tone levels and all accepted judgments, including levels chosen using the earlier noise match. The music remains a subjective cue for customary listening volume; mastering level, spectrum and crest factor vary, so the cue does not establish measured SPL, phon level or equivalence to every recording.

## Error metrics and stopping

The implementation addresses accumulated comparison drift and contour mismatch separately:

1. **Listening consistency:** Graph covariance estimates uncertainty after removing overall gain. The shape interval is `1.96 × sqrt(integral(point_variance, log_frequency) / log_frequency_span)`. Cross-check disagreement is RMS error between fitted and observed pair offsets. Global residual disagreement inflates uncertainty when redundant comparisons exist.
2. **Numerical PEQ fit:** The optimizer minimizes log-frequency-weighted curve error and changes in that error along the contour. It also penalizes tails outside the selected range and mildly penalizes large gains. Reports contain shape RMS, maximum shape error and accumulated contour mismatch `sum(abs(diff(shape_error)))` on the fit grid.

Listening stops when all sampled frequencies connect to actual observations, every node has at least two usable links, at least two independent graph cycles exist, estimated shape uncertainty is below `--shape-tolerance`, and cross-check RMS is below `--drift-tolerance`. New CLI profiles offer `doubt` (4 dB, cap 80 judgments/channel), `convinced` (3 dB, cap 150, default), and `obsessed` (2 dB, cap 300). All keep cross-check RMS at 1.5 dB. Explicit numeric flags override these choices. Saved profiles and the low-level `Settings()` defaults retain their earlier settings until explicitly changed. Budget exhaustion is reported as such rather than as convergence.

These caps control listening effort, not promised convergence counts or accuracy. Restricting comparisons to nearby frequencies can require more judgments to constrain accumulated uncertainty across the whole curve than distant links did. The stopping tolerances, cross-check requirements and caps are not weakened to compensate. Actual counts depend on listener responses, mode, skipped pairs, level bounds and response shape; simulations do not validate individual acoustic DF accuracy. Changing the tolerance preserves all saved evidence and recomputes status, with a smaller cap never discarding already accepted judgments.

The 95% intervals are conditional approximations under fixed response-model and independence assumptions. They exclude systematic listener bias, fit changes, incorrect hearing assumptions, interpolation error and unsampled features. Randomized order and repetition can reduce some errors, but cannot eliminate human bias. Numerical PEQ error describes approximation of the estimated correction, not acoustic target accuracy.

## Filters and export contract

The fitter uses APO/RBJ bell and shelving biquads with bounded damped least squares implemented in NumPy. Correction gains are limited to ±6 dB. Bell Q stays within 0.4–8; correction shelves fix Q to 1/√2 for monotonic transitions (shelf slope S = 1). It removes an overall in-band gain offset because the requirement concerns shape. Input attenuation uses a dense full-spectrum response grid and all filter centers, plus 1 dB margin.

`filter_mode=auto` evaluates bells only, a low shelf plus remaining bells, a high shelf plus remaining bells, and both shelves plus remaining bells, all at the same correction-band count. Optional shelves require sampled frequencies on both sides of their midpoint: low-shelf midpoints stay between the second and penultimate sampled frequencies and at or below 1 kHz; high-shelf midpoints stay between those interior bounds and at or above 2 kHz. Absent regions therefore do not receive unsupported shelves. Distinct midpoint ranges avoid complementary shelves at the same frequency contributing only an unidentifiable overall gain.

Bell initialization tries the previous uniform zero-gain layout and a residual-based layout. The latter greedily places filters using a small bank of candidate centers and Q values against the remaining curve and contour error; damped least squares then jointly refines them. The lower total optimization objective wins between these two bell starts. Shelf candidates use residual-based initialization, with shelf Q held fixed during optimization. A failed optional solver retains the working fallback.

The optimization objective retains the existing curve, contour, outside-range and gain penalties. Automatic filter-type selection compares the in-band curve-plus-contour component: the unmeasured shelf plateau is not required to return to zero merely because it lies outside the selected range. A replacement must improve that component by more than both 1% and 1e-6, require no more than 36 dB input attenuation, and have an absolute correction-only outside-range peak no larger than the greater of 6 dB and the bell fallback's outside-range peak (with 1e-6 dB numerical allowance). Otherwise the working candidate is retained. These are numerical selection bounds, not inferred acoustic behavior outside coverage.

Reports retain the selected topology, total optimization score, curve-plus-contour score, bell baseline scores, evaluated candidates and correction tail bound. `filter_mode=bells` uses the same improved bell initialization but does not evaluate correction shelves. Fitting mode can be saved from the profile menu or overridden for one export. Old profiles default to Auto; observations, hearing baseline, sampling schedule and stopping thresholds are unchanged.

The optional preference uses an [RBJ low shelf](https://www.w3.org/TR/audio-eq-cookbook/) with Q = 1/√2 (monotonic shelf slope S = 1), gain -12 to +12 dB and half-gain frequency 40–300 Hz (105 Hz by default). Three presets set only this midpoint: sub-bass at 60 Hz, balanced at 105 Hz, and warm at 180 Hz. With positive gain, the higher midpoint extends the bass lift farther into upper bass; with negative gain, the same regions are reduced. A requested +4 dB has an asymptotic +4 dB low-frequency plateau, +2 dB at the midpoint and 0 dB at high frequencies. This is relative to the calibrated DF baseline, not a claim of a flat acoustic headphone response.

With a nonzero preference, one of the requested export bands is reserved for the exact shelf and the remaining filters fit neutral correction. The preference shelf is then appended as native `Lo-shelf`; correction high shelves export as native `Hi-shelf`. Shape-fit error compares the exported correction with the estimated neutral correction plus the exact preference shelf: that shelf cancels in the difference, so the numerical error is the same as the neutral fit. Headroom and total outside-range response include the preference; the correction-only outside-range peak is also retained. Each filter's purpose is recorded in the report and preview, but is not added to the native Easy Effects filter schema. `--bass-db`, `--bass-hz` and `--filter-mode` on export override only that output; saved judgments and configuration are not rewritten. Older profiles without preference fields retain the same hearing baseline and default to 0 dB.
